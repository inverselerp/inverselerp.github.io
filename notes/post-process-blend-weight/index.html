Why post-process Blend Weight can surprise you

A smooth fade starts with a neutral parent material—not a specially named strength parameter.

Prepared from working notes with new conceptual diagrams. The described setup has not yet been reproduced or profiled in Unreal Engine.

You have a post-process material that looks right at full strength. You lower its Blend Weight, expecting the effect to disappear smoothly, but it stays visible or pops as the volume starts influencing the camera.

Before adding another control, inspect the default parameter values in the parent material.

The important distinction: for ordinary blendable post-process material instances, Unreal blends parameter values. Blend Weight is not a magic link to a parameter named Strength, and it is not necessarily a crossfade between two completely rendered images.

Give zero influence somewhere neutral to go

Epic’s documentation demonstrates a good setup with parent defaults that leave the input image unchanged: multiply by white, or use a Lerp alpha of zero.

Think of a simple, isolated scalar parameter like this:

// Simplified model for one instance blending from its neutral parent.
float value = lerp(ParentDefault, InstanceValue, Weight);

If the parent default and the instance value are both 1, blending between them still gives 1. There is no gradual reduction of that parameter as the weight approaches zero.

At zero influence the pass may not be rendered at all. If its parameter is already non-neutral as soon as it starts contributing, that can produce a visible pop.

Weight Parent 0, instance 1 Parent 1, instance 1
0.00 0.00 1.00
0.25 0.25 1.00
0.50 0.50 1.00
1.00 1.00 1.00

These are parameter values in the simplified model, not a prediction that the pass renders at weight zero or that perceived brightness changes linearly.

Make a minimal test material

Use a deliberately simple tint effect to isolate the behavior.

  1. Create a material with the Post Process material domain.
  2. Read the incoming color with SceneTexture, set to PostProcessInput0.
  3. Add a vector parameter named Tint, with a parent default of white.
  4. Add a scalar parameter named Amount, with a parent default of 0.
  5. Multiply the incoming color by Tint.
  6. Lerp between the untouched input and the tinted input using Amount.
  7. Connect the result to Emissive Color.
PostProcessInput0 ──────────────────────── Lerp A
PostProcessInput0 ── Multiply(Tint) ─────── Lerp B
Amount ────────────────────────────────── Lerp Alpha
                                         │
                                         └── Emissive Color

The math represented by that graph is:

// Conceptual expression, not a complete post-process shader.
float3 tinted = inputColor * Tint;
float3 outputColor = lerp(inputColor, tinted, Amount);

With Amount = 0, this returns the incoming color unchanged. The parent material therefore describes a neutral starting point.

Use a normal blendable configuration for this test, not a material that writes to a User Scene Texture. Keep the blendable location unchanged while comparing results.

Set up the instance and volume

Create a material instance from that parent. Override:

  • Amount to 1.
  • Tint to an obvious test color.

Assign the instance to a single Post Process Volume. Make the volume Unbound for the initial experiment so camera position and blend radius do not complicate the test.

Keep the material entry’s weight at 1, then vary the volume’s Blend Weight from 0 to 1. Disable other volumes and camera overrides while checking this isolated case.

Now make a deliberately bad variant: set the parent Amount to 1 and give its parent Tint the same non-white value as the instance. Compare the fade again.

This is a controlled way to inspect the neutral-default problem. After that works, test a bounded volume and walk the camera through its blend radius.

Neutral depends on the operation

Zero is not the correct default for every parameter.

Operation Usually neutral
Multiply the input color White / 1
Add a color offset Black / 0
Lerp from original to modified input Alpha 0
Add a UV offset Offset (0, 0)
Apply distortion Distortion strength 0

Check the complete graph. For example, setting a distortion strength to zero is only neutral if no other operation still changes the image.

For complicated effects, a final Lerp from the untouched input is often a useful place to define a clear zero-effect state. It does not automatically make the modified branch free to compute.

More than one parameter is blending

The volume does not search for Amount or Strength by name. Those are just parameter names chosen for readability.

Other blendable scalar and vector parameters can change as well. In the tint example, both Amount and Tint interpolate, so the visible result need not look like a linear fade between the two endpoint images.

Epic also calls out a subtle difference from the built-in post-process settings: an unchecked material-instance parameter override does not remove that parameter from material blending. Its inherited value still participates.

Static switches are a different mechanism; this is not a recipe for interpolating compiled shader permutations.

Know which weight and priority you are changing

Several controls affect the final result:

  • Volume Blend Weight: the contribution of that volume’s settings.
  • Blend Radius: the spatial transition around a bounded volume.
  • The material entry’s weight: the weight assigned to that blendable entry.
  • Volume Priority: ordering when volume contributions overlap.
  • Material Blendable Priority: rendering order between different blendable materials.

The one-parameter equation above is a mental model for the isolated test, not the full algorithm for every combination of overlapping volumes and materials.

For compatible instances of the same blendable material, Unreal can blend their settings into a shared material pass. That does not mean unrelated effects merge into one pass. Epic documents exceptions too: disabling Is Blendable makes instances render independently, and materials writing to User Scene Textures are not blended.

Before you add another workaround

Check the following in order:

  1. Does the parent material leave the input unchanged?
  2. Is the volume using the intended material instance?
  3. Are you changing the volume weight or the material entry weight?
  4. Are another volume, camera setting, or priority affecting the result?
  5. Are unoverridden parameters inheriting non-neutral values?
  6. Does the setup still blend as expected at the chosen location and in the target engine version?
